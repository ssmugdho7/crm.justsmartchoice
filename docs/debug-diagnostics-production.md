# Production debug diagnostics — 2026-10-23

The Utilities screen previously compressed eight tiles into a row, let inventory/log tables dominate the page, and read only 220 physical lines from three hard-coded CRM logs. Reversing the concatenated files placed older records first and discarded multiline traces. It did not capture browser errors. Production's default log threshold was zero, so important failures could disappear outside debug sessions.

This release keeps development diagnostics private in web requests, retains normal production error logging, adds request/module context without query strings or trace arguments, reads bounded tails from seven days of the configured CRM log location plus available PHP server logs, preserves multiline events, and orders them by timestamp. The administrator error report filters by module/type/search. Browser capture on visited administrator pages covers JavaScript errors, rejected promises, failed script/link/image resources, fetch and XHR failures. Collection requires administrator authentication, active debug mode, POST and a valid CSRF token even when global CSRF validation is disabled. It deduplicates and bounds reports per page/session. No form values, request/response bodies or query strings are collected; server-side reports redact recognizable credential fields.

Coverage is explicitly bounded: at most 500 events in the full report, at most 1 MiB per source, last seven days. Module classification is best effort from paths/context. This does not crawl unvisited pages, capture client-portal browser errors, remote browser consoles, swallowed errors, unavailable upstream logs, or every logical/business defect. Historical logs remain evidence after repair; they are not deleted to imply success.

Verified recurring causes repaired: Contact Role used unavailable SaaS permission labels; shared CRM/Chat/Recruitment labels were missing; Subcontractors used a deprecated settings registration API; proposal rows could expose a qualified ID while the bulk helper assumed `id`; the bulk script tag included a stray slash escape; Appointly's mixed Google SDK bootstrap aliased legacy classes before loading them. Legacy SDK interface return types were aligned with PHP 8 and nullable client parameters made explicit.
